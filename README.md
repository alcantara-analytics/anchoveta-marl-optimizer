# Anchoveta MARL Optimizer

Academic multi-agent decision and routing project for a homogeneous fleet of 15 anchoveta purse seiners operating from Malabrigo, Chimbote and Callao.

> **Evidence boundary:** this repository is public and does not contain the client probability grid. Simulated data and simulated vessel trajectories are explicitly labeled as such.

## What works now

The robust core is intentionally self-contained:

1. loads `MapProbabilidad_adulto.csv` locally **or** generates an explicitly labeled demo grid;
2. extracts spatially separated candidate fishing zones;
3. builds a navigation graph from valid grid cells;
4. computes A* routes from the three ports;
5. allocates all 15 vessels with Greedy and MILP baselines;
6. estimates homogeneous fuel cost from a documented reference scenario;
7. generates a map and optional GIF simulation;
8. writes `audit.json` recording whether the probability data were client-supplied or simulated.

The full research line can later add MAPPO and external oceanographic layers, but the command-line core is deliberately smaller so it remains reproducible and testable.

## Quick start

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

### Real/client input

Place your local file here; Git will ignore it:

```text
data/raw/MapProbabilidad_adulto.csv
```

Run:

```bash
python scripts/run_pipeline.py
```

### Fully reproducible demo

```bash
python scripts/run_pipeline.py --demo
```

The demo probability field is generated by code and is explicitly recorded as:

```text
SIMULATED_DEMO
```

The vessel movement shown in the GIF is also a **simulation**, not historical vessel tracking.

## Model assumptions

- 15 homogeneous agents: 5 per port.
- All agents share the same technical scenario parameters.
- Probability of presence is **not** treated as biomass or expected tonnes.
- Maximum vessels per zone is an experimental coordination constraint, not a claimed regulation.
- Fuel parameters are scenario/reference parameters unless replaced by client telemetry.

## External data strategy

The main CLI deliberately does not require Copernicus, ERA5, SISESAT, GEBCO or other large/credentialed downloads. Those sources can strengthen later versions, but the core model should not stop working when an external provider is unavailable.

## Tests and CI

GitHub Actions runs unit tests and a complete `--demo --no-gif` smoke test on every push/PR. The CI verifies that demo data are labeled as simulated.

## Local validation performed

Before publishing this repository structure, the pipeline was executed in both modes:

- **Demo mode:** passed; probability provenance = `SIMULATED_DEMO`.
- **Client-input mode:** passed locally against the supplied probability CSV; the client file is not committed.
